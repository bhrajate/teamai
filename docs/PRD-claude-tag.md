# PRD：对标 Claude Tag 的团队协作 AI 产品需求文档

Feature Name: claude-tag-collaboration
Updated: 2026-08-06
Status: Draft v1.0

## 1. 产品概述

### 1.1 背景

Anthropic 于 2026 年 6 月 23 日推出面向企业团队的群聊 AI 协作助理 **Claude Tag**，首站深度集成 Slack。其核心价值在于让 Claude 从"个人助理"转变为"团队虚拟同事"：在任意 Slack 频道中 @Claude 即可分派任务，Claude 读取频道历史上下文、自主拆解并执行任务、在子线程中汇报进度，支持持续学习、主动介入和跨数小时/数天的异步执行。

Anthropic 内部产品团队约 65% 的代码由 Claude Tag 参与完成。前 OpenAI 科学家 Andrej Karpathy 将其定义为"LLM 界面的第三次变革"——改变了 AI 在组织中以何种身份存在。

本 PRD 旨在对标 Claude Tag 的完整功能能力，定义我方产品"团队协作 AI"（以下简称 TeamAI）的产品需求。本产品将首先集成在主流企业通讯平台（Slack / 飞书 / 企业微信，首期以 Slack 为参考对标），作为团队共享的 AI 协作成员。

### 1.2 产品定位

TeamAI 是一个嵌入团队协作平台的共享 AI 协作成员，具备以下定位：

- 一个频道一个共享实例，团队全员共享上下文
- 从频道对话中持续学习并积累团队记忆
- 默认响应式，可开启环境行为（Ambient Mode）主动介入
- 支持长时间异步任务与定时任务
- 以独立 Agent 身份运行，具备完整权限管控与审计能力

### 1.3 目标

- 让团队无需切换应用即可与 AI 协作，消除"上下文切换"成本
- 将团队的背景知识沉淀为组织级记忆，减少重复解释与交接损耗
- 将重复性、可验证的工程任务（代码审查、Bug 修复、数据分析、文档编写）委托给 AI，释放人力
- 通过权限隔离与审计，使共享 AI 在企业中可治理、可追责

### 1.4 成功指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 频道激活率 | ≥ 60% | 已接入 TeamAI 的频道中，每周至少使用一次的比例 |
| 任务完成率 | ≥ 80% | @TeamAI 发起的任务中被成功执行并汇报的比例 |
| 任务接力率 | ≥ 30% | 频道内多位成员接力同一任务的比例 |
| 记忆复用率 | ≥ 40% | 新任务中自动引用频道历史知识的比例 |
| 人工返工率 | ≤ 20% | 需要人工修改 AI 产出的任务占比 |
| 审核通过率 | 100% | 所有 TeamAI 行为均可通过审计日志追溯 |

## 2. 调研分析：Claude Tag 功能拆解

### 2.1 定位对比

| 维度 | Claude Code | Claude Tag |
|------|-------------|------------|
| 主要用户 | 个人开发者 | 整个团队/频道 |
| 协作入口 | 终端 / IDE | Slack 频道 |
| 记忆范围 | 当前会话 + CLAUDE.md | 频道历史 + 授权跨频道记忆 |
| 任务调度 | 手动触发 | 主动 + 定时 + 条件触发 |
| 适用场景 | 代码生成、重构、调试 | 团队协调、跨职能任务 |

### 2.2 核心能力清单

1. **多人协作（Multiplayer）**：频道内共用一个 Claude 实例，所有成员共享上下文；成员可接力推进任务，查看彼此进展。
2. **持续学习（Team Memory）**：从频道对话中积累知识；用户用自然语言表达偏好后可被记住；可从被授权的其他频道学习（默认不读取私密频道）。
3. **主动介入（Ambient Mode）**：无需 @ 即主动跟进沉寂线程、标记重要信息、部署完成后主动通知；可监测 Bug 报告、创建修复 PR 并自动 @ 相关工程师。
4. **异步执行**：分派任务后自主运行数小时甚至数天，分阶段完成并汇报进度，期间可请求用户输入。
5. **工具调用**：连接 GitHub、Datadog、Salesforce、Sentry 等 API，可查数据、提 PR、做分析。
6. **上下文感知**：自动读取整个讨论串的历史消息，理解项目背景与决策脉络。
7. **定时/长期任务**：设置一次长期指令（如每周一汇总销售管道数据）持续运行。
8. **权限与治理**：管理员全局控制，组织级/频道级 token 上限，工具范围控制，跨频道学习授权默认关闭，操作日志透明可审计。

### 2.3 已知限制

- 仅面向 Enterprise 和 Team 客户，处于 Beta 阶段
- 仅支持 Slack 平台
- 底层固定使用 Claude Opus 4.8，不可切换低成本模型

## 3. 目标用户与使用场景

### 3.1 目标用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 团队负责人 | 工程/产品/运营负责人 | 任务透明可追踪、资源可控、知识沉淀 |
| 研发工程师 | 开发者 | 代码审查、Bug 定位修复、提 PR |
| 产品经理 | 数据与分析使用者 | 指标追踪、定期报告 |
| 支持与运维 | 客户支持、运维 | 工单处理、异常排查、部署通知 |
| 管理员 | 企业 IT / 平台管理员 | 权限管控、预算上限、审计合规 |

### 3.2 核心使用场景

- **S1 代码开发与审查**：@TeamAI 进行代码审查、生成功能实现、分析复杂 Bug 根因
- **S2 数据查询与分析**：@TeamAI 追踪关键指标、从连接的数据库/分析工具提取数据并生成定期报告
- **S3 支持工单处理**：分析工单模式、生成标准回复模板、自动处理常见问题
- **S4 文档协作**：委托撰写、润色、汇总技术文档
- **S5 主动监测**：Ambient Mode 下监测异常、部署状态、线程沉寂并主动通知

## 4. 功能需求

### 4.1 多人协作（频道共享实例）

**用户故事：** AS 团队成员，I want 在频道中与同事共享同一个 AI 实例并接力任务，SO THAT 无需各自重复上下文，团队协作更流畅。

**功能描述：**
- 一个频道部署一个共享 TeamAI 实例
- 频道内任意成员可 @TeamAI 发起任务
- 频道内所有成员可见任务进展，并可在已有任务上继续调整、接力推进
- 任务在子线程中执行与汇报，不打断主频道讨论

**验收标准：**
1. WHEN 成员在频道中 @TeamAI 发起任务，TeamAI SHALL 在子线程中确认任务并开始执行
2. WHEN 频道内任一成员接续某任务线程，TeamAI SHALL 基于该线程既有上下文继续执行，无需重新描述背景
3. WHILE 任务执行中，TeamAI SHALL 将执行进展同步到任务子线程，供频道成员实时查看
4. WHEN 两个成员在同一子线程中先后提出要求，TeamAI SHALL 合并两者上下文并在一次执行流中满足

### 4.2 持续学习与团队记忆

**用户故事：** AS 团队成员，I want TeamAI 记住频道中的背景知识与我的偏好，SO THAT 无需每次重复解释项目背景和约定。

**功能描述：**
- 从频道对话中自动提取并沉淀团队知识
- 用户可用自然语言声明偏好，TeamAI 记住并应用于后续交互
- 记忆按频道隔离；跨频道学习需管理员显式授权（默认关闭）
- 私密频道与私信内容默认不进入记忆
- 管理员可查看、编辑、删除记忆条目

**验收标准：**
1. WHEN 用户在频道中以自然语言表达某项偏好，TeamAI SHALL 记录该偏好并在后续相关任务中应用
2. WHEN 频道中出现新的项目背景讨论，TeamAI SHALL 提取关键信息并归入该频道记忆库
3. WHEN 用户引用历史讨论中的决策，TeamAI SHALL 从记忆库中检索并正确引用
4. WHILE 跨频道学习开关处于关闭状态，TeamAI SHALL 拒绝读取其他频道内容
5. IF 频道成员列表发生变更，TeamAI SHALL 通知管理员复核该频道记忆是否仍适合新受众

### 4.3 主动介入（Ambient Mode）

**用户故事：** AS 团队负责人，I want TeamAI 在未被 @ 时也能主动发现异常并提醒，SO THAT 问题能被及时暴露而不被遗漏。

**功能描述：**
- 开启 Ambient Mode 后，TeamAI 主动监控频道动态
- 主动跟进沉寂线程、标记重要信息、发现异常
- 可配置的主动行为规则（如：监测 Bug 报告、部署状态、PR 评审意见）
- 主动行为可被管理员按频道开关与限定范围

**验收标准：**
1. WHEN Ambient Mode 开启且频道出现符合主动规则的事件，TeamAI SHALL 主动发起提醒并 @ 相关成员
2. WHEN 频道某任务线程超过设定时间无更新，TeamAI SHALL 主动询问任务状态或提示相关成员
3. WHEN 部署完成或 CI 状态变化，TeamAI SHALL 主动向频道汇报结果
4. WHEN 管理员关闭某频道的 Ambient Mode，TeamAI SHALL 停止该频道的全部主动介入行为

### 4.4 异步与定时任务

**用户故事：** AS 团队成员，I want 把耗时任务交给 TeamAI 异步执行，SO THAT 我可以在它运行时处理其他工作。

**功能描述：**
- 任务可在子线程中长时间异步运行（数小时至数天）
- 任务执行期间分阶段汇报进度
- 执行过程需要用户输入时，主动请求并等待
- 支持定时/周期性任务（如每周一自动汇总）
- 支持任务状态查询、取消、指定负责人与停止条件

**验收标准：**
1. WHEN 用户分派一个长任务，TeamAI SHALL 拆解为多阶段并在子线程中异步执行
2. WHEN 任务进入新阶段，TeamAI SHALL 向子线程汇报当前进度
3. WHEN 任务执行需要用户决策，TeamAI SHALL 暂停并向用户请求输入，收到输入后继续
4. WHEN 用户设置定时任务，TeamAI SHALL 按设定周期自动触发执行并汇报结果
5. WHEN 达到设定的 token 预算上限，TeamAI SHALL 暂停任务并通知负责人

### 4.5 工具调用与系统集成

**用户故事：** AS 团队成员，I want TeamAI 调用 GitHub、监控、CRM 等系统工具，SO THAT 它可以自主完成查数据、提 PR、做分析等完整任务。

**功能描述：**
- 通过 Agent Identity 配置 API 连接
- 支持 GitHub（提 PR、读代码、评审）、Datadog/Sentry（监控告警）、Salesforce（CRM 数据）等工具
- 工具范围由管理员按频道/身份配置
- 工具调用需遵循该频道的权限包，不随个人权限变化

**验收标准：**
1. WHEN 用户请求需要外部工具，TeamAI SHALL 使用该频道已授权的工具执行，未授权时 SHALL 提示用户申请授权
2. WHEN 任务要求创建 PR，TeamAI SHALL 基于分析结果生成 PR 并附上说明
3. WHEN 任务要求查询指标数据，TeamAI SHALL 从已连接数据源获取数据并生成报告
4. WHEN 工具调用失败，TeamAI SHALL 记录错误并向用户说明失败原因与建议

### 4.6 权限管控与治理

**用户故事：** AS 企业管理员，I want 按频道/组织控制 TeamAI 的权限、预算与行为范围，SO THAT 共享 AI 在合规框架内运行。

**功能描述：**
- 管理员全局控制：组织级 token 消耗上限、频道级 token 消耗上限
- 每个 TeamAI 实例可访问的工具范围单独配置
- 跨频道学习授权（默认关闭）
- 频道级严格隔离：各频道实例记忆互不可见，私密频道内容不读取
- 独立 Agent 身份：独立账号与权限，所有操作可审计
- 操作日志完整记录：任务发起人、执行动作、工具调用、结果

**验收标准：**
1. WHEN 管理员设置组织级 token 上限，TeamAI SHALL 在达到上限后停止新任务并通知管理员
2. WHEN 管理员设置频道级 token 上限，TeamAI SHALL 在该频道达到上限后暂停任务并通知负责人
3. WHEN 任务发起，系统 SHALL 记录发起人、任务内容、执行时间等审计信息
4. WHEN 管理员查看审计日志，系统 SHALL 展示该频道的完整操作历史
5. WHILE 频道隔离启用，TeamAI SHALL 不读取任何其他频道及私密频道的内容

### 4.7 对话模板与标签（Tag 化复用）

**用户故事：** AS 团队成员，I want 为常见任务类型创建预设指令标签，SO THAT 激活标签后即可按预设角色与风格执行，无需重复说明。

**功能描述：**
- 支持创建自定义标签（如 code_review、report、brainstorm）
- 每个标签可预设指令、角色、输出风格
- 标签可按频道共享，团队成员可复用
- 激活标签后 TeamAI 按预设指令执行

**验收标准：**
1. WHEN 用户创建一个标签并填写预设指令，TeamAI SHALL 保存该标签供频道成员复用
2. WHEN 用户激活某标签发起任务，TeamAI SHALL 按该标签预设的角色、风格与指令执行
3. WHEN 管理员删除某标签，TeamAI SHALL 停止接受该标签的激活

## 5. 非功能需求

### 5.1 性能

1. WHEN 用户在频道中 @TeamAI 发起简单任务，TeamAI SHALL 在 5 秒内确认接收
2. WHEN 用户查询任务状态，TeamAI SHALL 在 2 秒内返回当前状态

### 5.2 安全与合规

1. TeamAI SHALL 不将私密频道内容用于任何训练或跨频道共享
2. TeamAI 的所有外部工具调用 SHALL 通过该频道的权限包鉴权
3. 审计日志 SHALL 保留至少 180 天，支持导出

### 5.3 可扩展性

1. TeamAI SHALL 支持单组织下创建多个相互隔离的频道实例
2. TeamAI SHALL 支持后续扩展至 Slack 之外的企业通讯平台（飞书、企业微信）

## 6. MVP 范围界定

### 6.1 MVP 包含

- 频道共享实例与多人接力（4.1）
- 频道内记忆与自然语言偏好（4.2 子集：频道内记忆）
- 基础工具调用（GitHub 集成）（4.5 子集）
- 异步任务与进度汇报（4.4 子集）
- 频道隔离与审计日志（4.6 子集）

### 6.2 MVP 不包含

- Ambient Mode 主动介入（4.3）→ 后续迭代
- 跨频道学习与管理员记忆管理界面（4.2 子集）→ 后续迭代
- 定时/周期性任务（4.4 子集）→ 后续迭代
- 对话模板与标签（4.7）→ 后续迭代

## 8. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 模型成本不可控 | 异步/主动任务消耗 token 激增 | 组织/频道级预算上限 + 主动任务模型分级 |
| 记忆污染或越权 | 共享记忆包含敏感信息 | 频道隔离 + 记忆管理界面 + 管理员审核 |
| 主动介入打扰用户 | Ambient Mode 过度触发 | 主动行为规则可配 + 频道开关 + 频控 |
| 责任边界不清 | 任务无人验收 | 明确负责人、停止条件、取消人，全部记录审计 |
